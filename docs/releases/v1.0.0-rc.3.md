# v1.0.0-rc.3 release candidate / 发布候选版

`v1.0.0-rc.3` is the final intentional public-contract refreeze before the
first stable 1.0 release. It adds production admission control and batch
resource limits while preserving the C ABI v1 structure size and all existing
field offsets. After this candidate, RC changes are limited to bug fixes.

`v1.0.0-rc.3` 是首个正式 1.0 发布前最后一次有意重冻结公共契约。本版补齐生产环境
所需的请求准入与批量资源限制，同时保持 C ABI v1 结构体总大小和所有既有字段偏移不变。
从本候选版开始，后续 RC 只修复 Bug，不再调整公共接口。

## Changes / 主要变更

- Bound the cpp-httplib task queue and OCR-engine wait queue with
  `max_queued_requests`.
- Return JSON `429 queue_full` when application admission is full and
  `503 engine_wait_timeout` when no engine becomes available before
  `engine_wait_timeout_ms`; both responses include `Retry-After: 1`.
- Wake blocked engine waiters during service shutdown.
- Add `max_batch_images`, `max_batch_total_pixels`, and
  `max_batch_decoded_bytes` to the HTTP configuration and C API configuration.
- Decode and infer recognition batches in chunks of eight, preserving result
  order and avoiding a second `cv::Mat` clone.
- Return C status `LW_PPOCR_STATUS_LIMIT_EXCEEDED` and HTTP
  `413 batch_limit_exceeded` for batch resource violations.
- Extract the engine pool from the HTTP service source and add deterministic
  unit, invalid-input, overload, recovery, contract, and CI coverage.
- Add a reproducible HTTP performance matrix tool, structured stress-test
  output, and a Windows local performance report.

- 使用 `max_queued_requests` 同时限制 cpp-httplib 底层任务队列和 OCR 引擎等待队列。
- 应用层等待队列已满时返回 JSON `429 queue_full`；超过
  `engine_wait_timeout_ms` 仍未获得引擎时返回 `503 engine_wait_timeout`；两者均携带
  `Retry-After: 1`。
- 服务停止时主动唤醒正在等待引擎的请求。
- HTTP 配置和 C API 配置新增 `max_batch_images`、`max_batch_total_pixels`、
  `max_batch_decoded_bytes`。
- 仅识别批量请求按 8 张分块解码和推理，保持结果顺序，并去除第二次 `cv::Mat` 复制。
- 批量资源超限时，C API 返回 `LW_PPOCR_STATUS_LIMIT_EXCEEDED`，HTTP 返回
  `413 batch_limit_exceeded`。
- 将引擎池从 HTTP 服务主文件中拆出，并增加确定性的单元测试、异常输入、过载、恢复、
  契约和 CI 门禁。
- 新增可复现的 HTTP 性能矩阵工具、结构化压力测试输出和 Windows 本机性能报告。

## Default production controls / 默认生产参数

```json
{
  "engine_instances": 1,
  "worker_threads": 4,
  "max_queued_requests": 32,
  "engine_wait_timeout_ms": 5000,
  "max_batch_images": 32,
  "max_batch_total_pixels": 40000000,
  "max_batch_decoded_bytes": 120000000
}
```

Tune these values using latency and memory measurements from the target
machine. Each engine instance loads an independent copy of all OCR models.

请根据目标机器的延迟和内存实测结果调整。每个引擎实例都会独立加载一套 OCR 模型。
