# v1.0.0 stable release / 正式版

`v1.0.0` is the first stable release of lw.PPOCR.OpenCVDNN. It provides a
compact, cross-platform PP-OCR inference runtime powered exclusively by OpenCV
DNN 5.0.0 on CPU, together with a stable C ABI, HTTP service, browser page,
C/C#/Python examples, deployment scripts, and downloadable packages.

`v1.0.0` 是 lw.PPOCR.OpenCVDNN 的首个正式稳定版本。项目仅使用 OpenCV DNN
5.0.0 CPU 推理，提供精简的跨平台 PP-OCR Runtime、稳定 C ABI、HTTP 服务、浏览器
调用页、C/C#/Python 示例、系统服务脚本和可直接部署的下载包。

## Stable contracts / 正式冻结的契约

The following v1 contracts are formally frozen with this release and remain
backward compatible throughout the 1.x line:

- C ABI v1 and its exported-symbol allowlist;
- HTTP API v1, including full OCR and recognition-only operations;
- HTTP service configuration Schema v1;
- JSONL access-log Schema v1;
- model-manifest Schema v1 and model/dictionary SHA-256 verification.

Breaking field removals, renames, type changes, semantic changes, or ABI
changes require a new major version or a separately versioned v2 contract.

以下 v1 契约从本版开始正式冻结，并在整个 1.x 系列保持向后兼容：

- C ABI v1 及导出符号白名单；
- HTTP API v1，包括完整 OCR 和仅识别接口；
- HTTP 服务配置 Schema v1；
- JSONL 访问日志 Schema v1；
- 模型清单 Schema v1，以及模型和字典 SHA-256 校验。

删除或重命名字段、修改字段类型或语义、破坏 ABI 等变更，必须进入新的主版本或单独
版本化的 v2 契约。

## Highlights / 主要能力

- Full OCR: text detection, optional orientation classification, and text
  recognition.
- Recognition only: single-image and batch inference for customer-supplied
  cropped text lines.
- Binary image HTTP bodies plus compatible JSON/Base64 requests.
- Browser UI with OCR boxes, recognized text, confidence, and stage timings.
- Optional `X-API-Key` authentication without logging secret values.
- Nginx-inspired split runtime/access logs, JSONL, request IDs, rotation,
  stage timings, and trusted-proxy handling.
- Bounded HTTP and engine wait queues, `429 queue_full`,
  `503 engine_wait_timeout`, and cumulative batch resource limits.
- Windows service scripts and Linux systemd install/start/stop/restart/uninstall
  scripts with offline unit verification.
- Docker and Docker Compose deployment for Linux AMD64.
- Reproducible performance, correctness, malformed-input, concurrency, RSS,
  ASan/UBSan, ABI, schema, package, and supply-chain checks.

- 完整 OCR：文字检测、可选方向分类和文字识别。
- 仅识别：支持客户已经裁剪好的单张或批量文字行图片。
- HTTP 支持图片二进制直传，同时兼容 JSON/Base64。
- 网页显示文字框、识别文本、置信度与各阶段耗时。
- 可选 `X-API-Key` 认证，启动输出和日志不会泄露密钥。
- 借鉴 Nginx 的 runtime/access 日志分离、JSONL、请求 ID、轮转、阶段耗时与可信代理。
- HTTP 和引擎等待队列有界，支持 `429 queue_full`、`503 engine_wait_timeout`
  和批量累计资源限制。
- Windows 服务脚本，以及支持离线 unit 校验的 Linux systemd 安装、启动、停止、重启、
  卸载脚本。
- Linux AMD64 Docker 与 Docker Compose 部署。
- 可复现的性能、正确性、异常输入、并发、RSS、ASan/UBSan、ABI、Schema、部署包和
  供应链门禁。

## Upgrade from RC.3 / 从 RC.3 升级

Use the complete 1.0.0 package instead of replacing individual executables or
libraries. Stop the installed service, back up `http-service.json` and the
required logs, extract 1.0.0 into a new directory, migrate only deliberate
local settings such as listen address, API Key, queue limits, and log paths,
then reinstall or restart the service and run `/health` plus real OCR. Keep the
RC.3 directory until rollback validation is complete.

请使用完整 1.0.0 包升级，不要只替换某个可执行文件或动态库。先停止服务，备份
`http-service.json` 和需要保留的日志，把 1.0.0 解压到新目录，只迁移监听地址、
API Key、队列限制和日志路径等明确的本地配置，然后重新安装或启动服务，并执行
`/health` 与真实图片 OCR。回滚验证完成前保留 RC.3 目录。

## Compatibility and limits / 兼容性与限制

- Official packages use OpenCV 5.0.0 and CPU inference only; OpenCV 4.x is not
  supported.
- Windows targets supported Windows 10/11 x64 systems.
- Linux x64 requires glibc 2.31 or newer; Linux ARM64 UOS 20 requires AArch64
  and glibc 2.28 or newer.
- macOS ARM64 is CI verified and ad-hoc signed, not Apple notarized.
- Linux packages do not bundle glibc or the ELF loader.
- Performance depends on image dimensions, text density, CPU, memory, and
  concurrency; benchmark on the deployment machine before tuning engines.

- 正式包固定使用 OpenCV 5.0.0，仅支持 CPU 推理，不支持 OpenCV 4.x。
- Windows 面向仍受支持的 Windows 10/11 x64。
- Linux x64 要求 glibc 2.31 或更高；Linux ARM64 UOS 20 要求 AArch64 与
  glibc 2.28 或更高。
- macOS ARM64 经过 CI 验证并使用 ad-hoc 签名，未经过 Apple 公证。
- Linux 包不包含 glibc 和 ELF 加载器。
- 性能受图片尺寸、文字密度、CPU、内存和并发影响，应在部署机器实测后调整引擎数。
