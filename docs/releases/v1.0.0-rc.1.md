# v1.0.0-rc.1 release candidate / 发布候选版

`v1.0.0-rc.1` begins the final stabilization period for the first stable
lw.PPOCR.OpenCVDNN release. Public interfaces are frozen. Until `v1.0.0`, only
bug fixes, test corrections, documentation corrections, and packaging fixes are
accepted; no public C ABI, HTTP API, configuration, log, or model-manifest
contract changes are planned.

`v1.0.0-rc.1` 进入首个稳定版本发布前的最终冻结期。公共接口已经冻结；在
`v1.0.0` 正式发布前，只接受 Bug 修复、测试修正、文档修正和打包修复，不再调整公共
C ABI、HTTP API、配置、日志或模型清单契约。

## Frozen v1 contracts / 已冻结的 v1 契约

- C ABI v1 and its nine-symbol export baseline.
- PP-OCR model-manifest Schema v1 with required hashes for bundled artifacts.
- HTTP API v1 for full OCR, single recognition, and batch recognition.
- HTTP service configuration Schema v1 with unknown-field rejection.
- JSONL access-log Schema v1, stable error codes, and request correlation IDs.

The numeric API and schema versions remain `1`; the product version is
`1.0.0-rc.1`. Frozen schema identifiers that point to their original v0.6.0
publication paths remain unchanged intentionally.

数值 API 与 Schema 版本仍为 `1`，产品版本为 `1.0.0-rc.1`。冻结 Schema 中指向
最初 v0.6.0 发布位置的标识符有意保持不变，避免无意义地改写契约哈希。

## Release gates / 发布门禁

- Windows x64, Linux x64, macOS ARM64, and Linux ARM64/UOS 20 baseline builds.
- Docker/Compose non-root deployment and health checks.
- Real-model native and HTTP inference.
- Golden OCR correctness for full OCR, cropped recognition, orientation, blank
  images, binary uploads, JSON/Base64, and ordered batches.
- Configuration, HTTP, and log contract tests.
- Malformed input, authentication, size-limit, and recovery tests.
- Concurrency, varied image sizes, RSS-growth checks, and the scheduled 5,000
  request Windows stability run.
- Linux ASan/UBSan, CodeQL, ABI export verification, dependency hashes,
  licenses, deterministic CycloneDX 1.6 SBOM, and package checksums.

## Upgrade from v0.7.0 / 从 v0.7.0 升级

1. Keep a backup of the old extracted directory and `http-service.json`.
2. Stop and uninstall an existing Windows service or systemd unit before moving
   its package directory.
3. Extract the RC into a new directory; do not overwrite a running directory.
4. Compare the old configuration with the bundled Schema v1 example. Preserve
   the API Key and intentional operational settings, but do not copy binaries,
   models, web assets, or libraries from v0.7.0 into the RC directory.
5. Start the RC from its launcher, verify `/health`, one full OCR request, one
   recognition-only request, the browser page, and logs.
6. Reinstall the service from the RC directory after validation.

No v1 API migration is required because the v1 contracts were frozen before
this RC. Roll back by stopping the RC service and reinstalling the untouched
v0.7.0 directory.

从 v0.7.0 升级不需要迁移 v1 接口。请保留旧目录与配置备份，在新目录解压候选包，按
Schema v1 对比并迁移必要配置；不要混用两个版本的可执行文件、模型、网页或动态库。验证
健康检查、完整 OCR、仅识别、网页和日志后，再从候选包目录重新安装系统服务。回滚时停止
候选服务并重新安装未修改的 v0.7.0 目录。

## Known limits / 已知限制

- This project supports OpenCV 5 only; OpenCV 4.x source builds are unsupported.
- Official inference is CPU-only. GPU backends belong to other projects.
- Linux packages require the documented CPU architecture and minimum glibc;
  glibc and the ELF loader are not bundled.
- The macOS artifact is ad-hoc signed and not notarized.
- API Key authentication does not provide TLS. Use a firewall or trusted reverse
  proxy with HTTPS for network exposure.
- This RC is intended for final validation and does not yet carry the stable
  `v1.0.0` support promise.
- Automated Dependabot update PRs are disabled. Pinned hashes, CodeQL,
  dependency review, scheduled verification, SBOM, and manual dependency review
  remain enabled.
