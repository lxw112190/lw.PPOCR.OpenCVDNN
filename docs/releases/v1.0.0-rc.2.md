# v1.0.0-rc.2 release candidate / 发布候选版

`v1.0.0-rc.2` is a packaging-fix candidate following `v1.0.0-rc.1`. It keeps
all frozen v1 public contracts unchanged and fixes Linux systemd installation
diagnostics and compatibility.

`v1.0.0-rc.2` 是继 `v1.0.0-rc.1` 之后的打包修复候选版。所有已冻结的 v1 公共
契约保持不变，本次只修复 Linux systemd 服务安装的兼容性与诊断能力。

## Changes / 变更

- Use the target machine's absolute `bash` path as the systemd `ExecStart`
  executable, then pass `run-http-service.sh` as its argument.
- Write `WorkingDirectory=` as a systemd-escaped absolute path without outer
  quotes. openEuler 22.03 SP1/systemd 249 treats those outer quotes as path
  characters and otherwise rejects the unit as a non-absolute path.
- Add `./install-service.sh --verify-only` to validate the generated unit
  without installing it.
- Validate the generated unit with `systemd-analyze verify` before replacing
  `/etc/systemd/system/lw-ppocr-opencvdnn.service`.
- Separate service enable and restart operations. On failure, print the unit,
  full service status, and the latest 80 journal records.
- Add generated-unit parsing to the Linux x64 CI package gate.

- systemd 的 `ExecStart` 改为目标机绝对 `bash` 路径，并把
  `run-http-service.sh` 作为参数传入。
- `WorkingDirectory=` 改为经过 systemd 转义且不带外围引号的绝对路径；openEuler
  22.03 SP1/systemd 249 会把外围引号当作路径字符，进而将 unit 拒绝为非绝对路径。
- 新增 `./install-service.sh --verify-only`，无需安装即可验证生成的 unit。
- 覆盖 `/etc/systemd/system/lw-ppocr-opencvdnn.service` 前，使用
  `systemd-analyze verify` 检查配置。
- 拆分服务启用与重启步骤；失败时自动输出 unit、完整状态和最近 80 条 journal 日志。
- Linux x64 CI 新增发布包 systemd unit 解析门禁。

## Frozen contracts / 冻结契约

There are no changes to the C ABI v1 export baseline, HTTP API v1,
configuration Schema v1, access-log Schema v1, model-manifest Schema v1, OCR
response fields, model files, or dictionary hashes.

C ABI v1 导出基线、HTTP API v1、配置 Schema v1、访问日志 Schema v1、模型清单
Schema v1、OCR 响应字段、模型文件与字典哈希均未改变。

## Linux systemd verification / Linux systemd 验证

The installer fix was verified on a physical AArch64 machine running
openEuler 22.03 LTS-SP1, glibc 2.34, and systemd 249. The test used the RC.1
binary/model payload with the RC.2 installer script: unit validation,
installation, enablement, startup, `/health`, real-image OCR, restart recovery,
and the port listener all passed. The exact RC.2 CI archive must still be
downloaded and retested before the RC.2 tag is published.

安装脚本修复已在 openEuler 22.03 LTS-SP1、glibc 2.34、systemd 249 的 AArch64
实体机上验证。测试组合为 RC.1 二进制/模型与 RC.2 安装脚本；unit 校验、安装、开机
启用、启动、`/health`、真实图片 OCR、重启恢复和端口监听均通过。发布 RC.2 标签前，
仍需下载 CI 生成的完整 RC.2 压缩包并重新验证，避免把“补丁组合验证”等同于“正式附件
验证”。

Run from the extracted package directory:

```bash
./install-service.sh --verify-only
sudo ./uninstall-service.sh
sudo ./install-service.sh
systemctl --no-pager --full status lw-ppocr-opencvdnn.service
curl http://127.0.0.1:8787/health
```

The installer records the current absolute package path. Uninstall the service
before moving or deleting that directory.

安装脚本会记录当前发布包的绝对路径。移动或删除该目录前，必须先卸载服务。
